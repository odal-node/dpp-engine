# 0.16.0 verification record

Every pull request merged since v0.15.0 is traced to the CHANGELOG entry that describes it. Every entry's claims are checked against the code at the release commit. Every issue those pull requests closed is checked against what it asked for. Corrections land in `CHANGELOG.md` in the same change as this record, before the tag. `docs/governance/RELEASE.md` makes this record a step of every release.

- **Range:** `v0.15.0` (`6733e9f8`) to `main` at `1f32e7b7`.
- **Checked against:** `main` at `1f32e7b7`. The release commit adds only the version bump and the entries of #576, which merges before it and is checked in its own pull request.
- **Date:** 2026-11-12.

## How each claim was checked

A claim is **verified** when the code at the release commit does what it says. Evidence is one of:

- the source location that implements it;
- a test that pins it, by name. Every test named below is in a suite that passed on 2026-11-12 on `main` with #576 merged in: `just check`, and the `dpp-dal`, `dpp-vault`, `dpp-plugin-host` and `dpp-node` integration tiers;
- the upgrade and onboarding paths, which `operator_paths.rs` runs on every pull request against the real binaries.

Every backticked path and identifier in the section was also checked mechanically, to confirm it exists outside the CHANGELOG. Of 150, nine do not appear verbatim, and all nine are legitimate:

- five routes, which appear in the API description under the `/vault` prefix the node mounts;
- `complianceResult.repairabilityIndex`, a path into a schema that defines `repairabilityIndex`;
- `odal.passport_transfer.revision`, the column `0047_passport_transfer_revision.sql` adds;
- `Caused by:`, the label `anyhow` prints, quoted to describe the old behaviour.

**Entry corrected:**

- **A submission past the first thousand tasks on the dashboard is found (#484):** it said a long task list "is now read from both ends, interleaved, since the order is not recorded". #490, in the same release, asks the registry for newest first and reads from the front once the first page proves that order. Both ends are read only when the order cannot be told. The entry now says so and points at the **Changed** entry.

**Found while checking, outside the changelog:**

- **The standards register's RFC 3279 row omitted the specification that RFC obsoletes.** The RFC Editor's page lists it. Corrected in the same change, which is also this release's re-read of the register (step 7 of the checklist). Every other row matched its source and its `Read` date is now 2026-11-12. The GS1 row still names 1.2.1, the latest release listed.
- **A credential narrowed to a withdrawn product category is refused at issuance.** Category-scoped issuance (#507) checks the requested values against the current schema's list, so a value that only an earlier schema version allows (an electronics `laptop` from before `v1.2.0`) is refused, although stored passports state it. The entry's description of the check is accurate for this release. The list of every version's values is a dpp-core change, and the switch to it is part of the dpp-core 0.24.0 repin (#600).
