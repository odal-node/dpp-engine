# 0.15.0 verification record

Every pull request merged since v0.14.0 is traced to the CHANGELOG entry that describes it, every entry's claims are checked against the code at the release commit, and every issue those pull requests closed is checked against what it asked for. Corrections land in `CHANGELOG.md` in the same change as this record, before the tag. `docs/governance/RELEASE.md` makes this record a step of every release.

- **Range:** `v0.14.0` (`5e43ab60`) to `main` at `24304e5d`.
- **Checked against:** `main` at `24304e5d`. The release commit adds only the version bump and the entries of the pull requests that merge before it (#567, #568, #569), each checked in its own pull request.
- **Date:** 2026-11-03.

## How each claim was checked

A claim is **verified** when the code at the release commit does what it says. Evidence is one of:

- the source location that implements it;
- a test that pins it, by name (every test named below is in a suite that passed on 2026-11-03: `just check`, and the `dpp-dal`, `dpp-vault`, `dpp-plugin-host` and `dpp-node` integration tiers);
- a run against a real node, for the upgrade and onboarding paths, which `operator_paths.rs` now repeats on every pull request.

Every backticked path and identifier in the section was also checked mechanically to exist outside the CHANGELOG. Four did not, and all four are legitimate: a git-ignored file, and names the entry describes as removed.

**Entries corrected:**

- **Product group data carries a `productIdentifier`:** gave the mandatory battery field counts as 45, 44 and 37, which was dpp-core 0.21.0's. In this release dpp-core 0.22.0's 41, 40 and 33 holds, as the battery-guidance entry and the API description say.
- **Trusted lists verify on the released `xml-sec`:** said `dpp-seal` requires 0.1.20. This release moves it to 0.4.1, built to verify only.
- **`rustls-webpki`, `webpki-roots`, NATS websockets:** said `tokio-websockets` and the `webpki-roots` 0.26 copy stay in `Cargo.lock` because `async-nats` 0.50 is the newest release. In this release `async-nats` is 0.51, and neither crate is in the lock.

**Moved by the release pull request (#560):** E14 and E16 were filed under **Added** and refuse requests 0.14.0 accepted: a third concurrent import gets `429`, and a write that stores a personal-data field without a statement gets `422`. Step 2 of the checklist puts a break under **Breaking**, so both moved there unchanged, each with a migration note.

**Found while checking, outside the changelog:**

- **The public read of a retired, never-published draft answers `500`, not `404`.** Core allows `Draft → Retired`, and `serves_publicly(Retired)` assumes a publish. Unchanged since v0.14.0. #570, for 0.16.0.
- **Archived versions store the lens's reading, not the stored bytes.** `ArchivingPassportRepo` and the state-change log serialise the loaded passport into `passport_version`, so a version archived from a passport stored before a lens hop carries a shape it was never signed in. #571, for 0.16.0.
- **`odal bootstrap` with wrong admin credentials prints "could not reach the node … is it running?"** That sends an operator to the network instead of the password. #572.
