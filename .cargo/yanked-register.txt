# Yanked crates the security audit tolerates, and for how long.
#
# `cargo audit --deny yanked` fails on any yanked crate and has no way to name
# one it should leave alone: its `--ignore` takes advisory IDs, and a yanked
# crate has none. `scripts/check-yanked.sh` is the audit gate instead. It keeps
# `--deny yanked` and `--deny unmaintained`, fails on every vulnerability, and
# lets a yanked crate through only when this file names that exact version.
#
# An entry is a loan, not a decision:
#   - it names one crate at one version, so a second yanked crate, or the same
#     one at another version, fails the audit;
#   - `expires` has to be within 60 days of `recorded`, and an expired entry
#     fails the audit, which forces somebody to look again;
#   - an entry that matches nothing fails the audit, so the line is removed the
#     day the crate leaves the tree rather than left to rot.
#
# Entries are blocks of `key: value`, a block starting at `crate:`. A value may
# wrap onto lines that start with whitespace. Every key below is required.

crate:      zip
version:    8.6.0
path:       dpp-integrator -> calamine -> zip
rationale:  Yanked upstream, and it cannot be replaced from here. Every zip from
            8.0.0 through 9.0.2 is yanked and only 9.0.3 and later are live, but
            calamine 0.36.1, its latest release, requires zip ^8.6, so calamine
            pulls 8.6.0 into the
            tree whatever this workspace asks for. A direct bump to 9.0.x would
            leave 8.6.0 in place for calamine and put two zip versions in the
            build, which dpp-integrator avoids on purpose: its direct zip,
            used to pre-scan XLSX for zip and dimension bombs, is
            version-matched to calamine's. Git sources are denied (deny.toml),
            so patching in a calamine fork is not an option either. Yanking is
            the maintainer's "do not use", and this is a bounded exception to
            it, not agreement with it.
owner:      LKSNDRTMLKV
recorded:   2026-10-16
expires:    2026-12-15
release-on: calamine releases a version that requires zip 9 (tafia/calamine#741).
            Then bump calamine and the direct zip together in one change (zip
            9.0.3 or later), adjust the `entry.name()` calls in xlsx_parser.rs
            to whatever zip 9 returns, re-run the XLSX bomb tests, and delete
            this entry.
